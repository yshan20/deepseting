# Переносимые правила Codex

Явные правила репозитория имеют приоритет над глобальными настройками.

## Project Orchestration Router

Определи режим до создания проектных документов:

1. Отдельная строка `PROJECT_ORCHESTRATION_MODE: GAME_MASTER_PLAN` в корневом `CLAUDE.md` включает `GAME_MASTER_PLAN`.
2. Отдельная строка `PROJECT_ORCHESTRATION_MODE: STANDARD_DEEPSETING` явно выбирает обычный режим, даже если существует sentinel.
3. Без объявления файл `specs/master/ACTIVE_STAGE.md` включает `GAME_MASTER_PLAN`.
4. Иначе следуй существующим соглашениям репозитория. Не создавай процессные документы автоматически.

Регистр значения значим; пробелы по краям допустимы. Неизвестные и несколько объявлений — ошибка конфигурации.

В `GAME_MASTER_PLAN` `specs/master/` определяет допуск и порядок работы, а `specs/labs/` — правила подсистем. Не создавай параллельные `docs/SPEC.md`, `docs/features/`, `docs/plan.md` или корневой `PROGRESS.md`, если Master Plan явно их не требует. Для продолжения восстанови активную Stage, Wave, HANDOFF и Lab task. Подробности — в `skills/project-specifications/references/game-master-plan.md`.

В обычном режиме используй документацию, уже принятую в репозитории. Не вводи обязательный approval, список вопросов, progress log или scaffolding. Навык `project-specifications` применяй только по его узким условиям срабатывания.

## Формат ответов

- Shell-команды выдавай одной строкой, без переносов через `\`.
- Пути указывай в формате `файл:строка`.

## Игровые ассеты

Перед существенной работой с игровыми ассетами используй `game-creation-patterns`, если навык установлен. Повторно используй проверенный рецепт при тех же условиях; новый поиск нужен при смене подхода, версии, инструмента, существенной неопределённости или неудаче.

При создании моделей по умолчанию обучай пользователя по шагам; самостоятельное моделирование требует однозначного поручения. Текстуры, анимацию и код выполняй самостоятельно в пределах запроса. При старте новой игры организуй исходники и импортируемые ресурсы с учётом движка и существующей структуры.
