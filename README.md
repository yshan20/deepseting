# Обвязка Claude Code (репозиторий `deepseting`)

Переносимые настройки Claude Code: глобальные правила разработки, `settings.json`, скилл ведения
спецификаций и генератор каркаса нового проекта. Один `git clone` + один скрипт — и на новой машине
тот же рабочий процесс.

Репозиторий раньше хранил настройки DeepSeek Harness (`~/.dsh`); теперь всё переведено на Claude Code
(`~/.claude`). Историческое имя репозитория оставлено, чтобы не ломать существующие ссылки и клоны —
см. [Что изменилось при переносе](#что-изменилось-при-переносе).

## Структура

| Путь | Что это |
| --- | --- |
| `claude/CLAUDE.md` | Глобальные правила разработки; ставится в `~/.claude/CLAUDE.md` и подмешивается в каждую сессию. |
| `claude/settings.json` | Настройки Claude Code: модель, усилие рассуждения, тема, режим прав. |
| `claude/skills/project-specifications/` | Скилл ведения спецификаций проекта и шаблоны документов. |
| `bin/new-project.ps1` | Генератор каркаса спецификаций и pre-commit хука в новом проекте. |
| `install.ps1` | Разворачивает всё перечисленное в каталог настроек Claude Code. |
| `tests/` | Тесты установки и генератора; см. [tests/README.md](tests/README.md). |

Всё, что лежит внутри `claude/`, повторяет структуру `~/.claude` один в один: установка — это копирование
дерева плюс аккуратное слияние `settings.json`.

## Установка на новой машине

```powershell
git clone https://github.com/yshan20/deepseting.git
cd deepseting
pwsh -File install.ps1
```

Требования: PowerShell 7+ (`pwsh`) либо Windows PowerShell 5.1 — скрипты совместимы с обоими,
и вместо `pwsh` можно писать `powershell -ExecutionPolicy Bypass -File install.ps1`. Для генератора
и хука нужны `git` и `sh` (подходит тот, что ставится вместе с Git for Windows).

Что делает скрипт:

- кладёт `claude/CLAUDE.md` в `~/.claude/CLAUDE.md`;
- **сливает** `claude/settings.json` с существующим `~/.claude/settings.json`, а не перезаписывает его:
  ключи из репозитория побеждают, всё остальное (плагины, хуки, выданные права) остаётся на месте;
- ставит скилл в `~/.claude/skills/project-specifications` (каталог предварительно очищается, иначе
  в нём остаются шаблоны, удалённые из репозитория);
- кладёт генератор в `~/.claude/bin/new-project.ps1`.

Каждый изменяемый файл, содержимое которого отличается от нового, сохраняется рядом как `*.bak-<дата>`.
Повторный запуск ничего не ломает и лишних копий не плодит.

Каталог настроек выбирается так: аргумент `-ConfigDir`, иначе переменная `CLAUDE_CONFIG_DIR`,
иначе `~/.claude`. Скрипт неинтерактивен — ничего не спрашивает и подходит для CI.

После установки перезапусти Claude Code. Ключ API в репозитории не хранится: вход — командой `claude`
и `/login` либо через переменную окружения `ANTHROPIC_API_KEY`.

## Настройки

```json
{
  "model": "opus",
  "theme": "dark",
  "permissions": { "defaultMode": "auto" },
  "enableWorkflows": true,
  "autoUpdatesChannel": "latest",
  "tui": "fullscreen"
}
```

- `model` — алиас модели; в `settings.json` это строка, объектная форма с усилием тут не принимается.
  Усилие рассуждения задаётся на сессию: `/effort high` в сессии или `claude --effort high` при запуске
  (уровни `low` / `medium` / `high` / `xhigh` / `max`, значение запоминается локально).
- `permissions.defaultMode: auto` — режим, в котором агент работает без подтверждения каждого шага.
  Полный обход проверок — это `bypassPermissions`; меняй осознанно.
- Списка включённых плагинов (`enabledPlugins`) здесь нет намеренно: плагины зависят от установленных
  на машине маркетплейсов, и перенос их «вслепую» ломает запуск.

## Спецификации и проверяемость

- Критерии готовности в `docs/features/<имя>.md` — таблица с обязательной колонкой «Чем проверяется»;
  пустая правая колонка считается плохо сформулированным критерием.
- Критерии готовности утверждает человек до начала работы над планом: агент показывает их и ждёт подтверждения.
- `new-project.ps1` при создании каркаса добавляет git pre-commit хук в `.githooks/pre-commit`
  (подключается через `core.hooksPath`, в индекс попадает с режимом `100755` и переводами строк LF —
  иначе вне Windows git пропускает его молча).

### Что проверяет хук

Проверяется **содержимое индекса** — то, что реально уйдёт в коммит, а не файлы в рабочем дереве.
Незакоммиченный черновик в рабочем дереве коммит не блокирует, а уже подготовленная к коммиту пустая
колонка не проходит, даже если на диске она давно заполнена.

Коммит отклоняется, если:

- в критериях готовности есть строка с пустой колонкой «Чем проверяется»;
- в строке критерия этой колонки нет вовсе (строка короче заголовка таблицы);
- в разделе «Критерии готовности» нет таблицы с колонкой «Чем проверяется» — иначе проверку можно было бы
  снять, удалив заголовок;
- изменён `docs/plan.md`, но не изменён `PROGRESS.md`.

Колонка ищется по заголовку таблицы, а не по номеру, поэтому число колонок и их порядок значения не имеют.
Проверяются файлы `docs/features/*.md`; архив завершённых функций в `docs/features/done/` не проверяется.
В тексте ошибки — имя файла и номер строки.

## Новый проект

```powershell
pwsh -File ~/.claude/bin/new-project.ps1 <путь-к-проекту>
pwsh -File ~/.claude/bin/new-project.ps1 <путь-к-проекту> -Feature <имя-функции>
```

Создаёт `README.md`, `docs/SPEC.md`, `docs/plan.md`, `PROGRESS.md`, папку `docs/features/` и git pre-commit хук.
Существующие файлы не затираются.

## Тесты

```powershell
pwsh -File tests/run-tests.ps1
```

Проверяются установка (включая слияние настроек и идемпотентность), генератор каркаса и поведение
pre-commit хука на настоящем git-репозитории. Подробности — в [tests/README.md](tests/README.md).

## Что изменилось при переносе

| Было (DeepSeek Harness) | Стало (Claude Code) |
| --- | --- |
| `~/.dsh/AGENTS.md` | `~/.claude/CLAUDE.md` (`claude/CLAUDE.md` в репозитории) |
| `~/.dsh/settings.yaml` | `~/.claude/settings.json` (`claude/settings.json`) |
| `~/.dsh/skills/project-specifications` | `~/.claude/skills/project-specifications` |
| `~/.dsh/bin/new-project.ps1` | `~/.claude/bin/new-project.ps1` |
| `agent-default-model: deepseek-v4-pro` | `"model": "opus"` |
| `reasoningEffort: high` | Ключа в `settings.json` нет: `/effort high` в сессии или `claude --effort high`. |
| `permission.defaultPreset: danger-full-access` | `"permissions": { "defaultMode": "auto" }` |
| `ui-theme.preference: dark` | `"theme": "dark"` |
| `agent-presets.default: cordis` | Прямого аналога нет — пресет отброшен. |
| `.credentials.yaml` с `DEEPSEEK_API_KEY`, запрос ключа при установке | Вход через `/login`; установщик стал неинтерактивным. |
| `DSH_HOME` | `CLAUDE_CONFIG_DIR` (либо `-ConfigDir`) |

## Безопасность

Репозиторий не содержит секретов. Учётные данные (`~/.claude/.credentials.json`), идентификаторы машины
и данные сессий исключены через `.gitignore`. `install.ps1` не пишет секреты и не запрашивает ключи.
