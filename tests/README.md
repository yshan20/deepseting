# Тесты обвязки

Один скрипт — `run-tests.ps1`. Внешних зависимостей нет: только PowerShell (5.1 или 7+), `git`
и `sh` (подходит тот, что идёт с Git for Windows — им же git запускает хуки).

## Запуск

```powershell
pwsh -File tests/run-tests.ps1
pwsh -File tests/run-tests.ps1 -Keep   # оставить tests/.tmp для разбора
```

Скрипт печатает по строке на проверку, в конце — счётчик, и завершается кодом `1`, если хоть одна
проверка провалилась. Всё создаётся во временном каталоге `tests/.tmp` (в `.gitignore`); настоящий
`~/.claude` и настоящие проекты не затрагиваются — установщик вызывается с `-ConfigDir`.

## Что покрыто

| Группа | Что проверяется |
| --- | --- |
| Установка с нуля | `CLAUDE.md`, `rules/*.md`, `settings.json`, скилл с шаблонами и генератор оказываются на своих местах; модель, усилие рассуждения и режим прав доезжают до файла настроек, а ключи со значением по умолчанию в него не попадают. |
| Слияние настроек | Чужие ключи (`statusLine`, `permissions.allow`) переживают установку, ключи репозитория побеждают в конфликте, прежняя версия файла сохраняется как `settings.json.bak-<дата>`. |
| Правила по темам | Личное правило рядом с правилами обвязки не удаляется, одноимённое правило обновляется, а его прежняя версия сохраняется как `<имя>.bak-<дата>`. |
| Повторный запуск | Вторая установка подряд не меняет содержимое и не плодит резервные копии. |
| Каркас проекта | `new-project.ps1` создаёт документы спецификаций, заготовку функции и `.githooks/pre-commit`, а также подключает хук через `core.hooksPath`. |
| Хук: пустой критерий | Коммит с пустой колонкой «Чем проверяется» отклоняется, и в тексте ошибки есть имя файла. |
| Хук: заполненный критерий | Тот же файл с заполненной колонкой коммитится. |
| Хук: критерии без колонки | Раздел «Критерии готовности» без колонки «Чем проверяется» отклоняется. |
| Хук: архив `done/` | Файлы в `docs/features/done/` не проверяются даже с пустой колонкой. |
| Хук: план без прогресса | Коммит с изменённым `docs/plan.md` без `PROGRESS.md` отклоняется; вместе с `PROGRESS.md` — проходит. |
| Router и initializer | `orchestration-tests.ps1`: standard, marker, fallback, явный standard поверх sentinel, whitespace, inline example, invalid/duplicate marker; запуск установленного генератора. |
| Сохранность Game Master Plan | Нет конфликтующих новых файлов; хеши существующих файлов и hooks config сохраняются, включая запуск из подпапки. |
| Mode-aware hook | Реальные коммиты в обоих режимах, staged/unstaged marker/sentinel, удаление sentinel и возврат стандартных проверок. |
| Сохранность установки | Detector/reference установлены; локальные изменения навыка сохранены в backup, повторная установка идемпотентна. |

`orchestration-tests.ps1` загружается основным runner и отдельно не запускается.
Если `awk`/`sh` не находятся, добавьте каталог `usr/bin` установленного Git for Windows в PATH
текущего терминала перед запуском тестов. Нужны также `grep`, используемый стандартным hook.
Acceptance F/G проверяются ревью правил: сценарии continue, пять условий pre-approval,
уровни 0–3, cross-Lab совместимость, память/checkpoint. Автотесты не доказывают поведение LLM.

Проверки хука идут через настоящий `git commit` во временном репозитории, а не вызовом скрипта
напрямую: так же, как хук отработает у пользователя, вместе с индексом и `core.hooksPath`.

## Как добавить проверку

1. Добавь блок в конец `run-tests.ps1` перед секцией «Итог».
2. Состояние готовь через `Set-Text` (пишет UTF-8 без BOM и с LF — важно для файлов, которые читает `sh`)
   и `Invoke-Git` (не срывает выполнение на ненулевом коде возврата git).
3. Результат фиксируй через `Check <имя> <условие> [<детали при провале>]` — счётчики и код возврата
   считаются автоматически.
4. Опиши новую проверку в таблице выше.
