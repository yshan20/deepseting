# Глобальные правила разработки

Эти правила действуют для всех проектов и всех сессий. Применяй их при написании кода и документации.

## Доменная архитектура

- Структурируй код по доменам (предметным областям), а не только по техническим слоям (контроллеры, сервисы, модели и т. п.).
- Группируй файлы так, чтобы любой агент мог понять назначение кода, читая один домен целиком, без необходимости просматривать весь проект.
- Используй явные имена и понятные границы модулей, минимизируй скрытые зависимости.

## Структура проекта — корень

- В корне каждого проекта всегда создавай файл `README.md` с кратким описанием структуры проекта.
- В нём кратко описывай: назначение проекта, список основных каталогов и что в них находится, а также как запускать, собирать и тестировать проект.

## Подробные описания в подпапках

- В каждой ключевой подпапке направления (например, `frontend`, `backend`, `tests`) держи подробное описание этого направления — отдельный `README.md` внутри подпапки.
- Особенно подробно описывай тесты: какие тесты существуют, как их запускать, что они покрывают и как их расширять.
