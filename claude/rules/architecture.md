# Архитектура и структура проекта

## Доменная архитектура

- Структурируй код по доменам (предметным областям), а не только по техническим слоям
  (контроллеры, сервисы, модели и т. п.).
- Группируй файлы так, чтобы назначение кода читалось по одному домену целиком,
  без просмотра всего проекта.
- Используй явные имена и понятные границы модулей, минимизируй скрытые зависимости.

## Обобщаемость

- Решение должно обобщаться на невидимые случаи и не должно быть подогнано под какой-либо
  набор примеров или фикстур.
- Элегантная архитектура — это не эстетика, а способность обобщаться.

## README проекта и подпапок

- В корне каждого проекта держи `README.md`: назначение проекта, список основных каталогов
  и что в них находится, как запускать, собирать и тестировать проект.
- В каждой ключевой подпапке направления (например, `frontend`, `backend`, `tests`) держи
  отдельный `README.md` с подробным описанием этого направления.
- Особенно подробно описывай тесты: какие тесты существуют, как их запускать, что они покрывают
  и как их расширять.
